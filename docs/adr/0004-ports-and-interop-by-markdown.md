# Ports for the core; interop by shared markdown

Daily Task Panel's core declares three narrow ports (`core/ports.ts`) for everything it needs from the outside world, and one adapter implements each: a **task source** (read the vault's tasks, toggle completion, signal change — the Tasks plugin's object shapes, plugin id, and event names live behind this seam in `adapters/tasks-plugin.ts`), a **project store** (frontmatter reads and writes, lifecycle, creation), and a **line editor** (every other task-line write, fingerprint-verified and journaled). `adapters/compose.ts` wires implementations to ports; the view is the composition root that hands ports plus pure core functions to the UI. The clock is not a port: `today` is an injected value, and core never reads it (ADR-0001's stateless projection is reaffirmed — ports return live projections; nothing caches tasks or mints identifiers). No second implementation ships; a port's value here is the named contract and the single file vendor internals can break in, not hypothetical substitution.

**Interop is by shared markdown, not by runtime API.** Tasks are text, so any plugin that reads or writes checkbox lines composes with Daily Task Panel by construction; Daily Task Panel exposes no API object and calls no other plugin's beyond the explicit compat points. What Daily Task Panel reads: checkbox lines via the Tasks plugin's parser (emoji format only), project frontmatter (`status`, `deadline`, `order` — ADR-0005, `start` — ADR-0006), the Daily Notes core plugin's folder/format config. What it writes: single task lines (schedule/cancel edits and cross-note moves, always verified against a read-time fingerprint), project frontmatter, and completion — which goes through the Tasks plugin API or not at all, so ✅ done-dates, recurrence, and sync write-backs keep working. What it promises never to touch: daily-note `# Events:` sections (Day Planner's, ADR-0003), the machine-managed note beyond check-off (any sync tool's, ADR-0003 as amended), and any line the user didn't act on. The configurable move-target heading is the Kanban compat point: a project note that becomes a board keeps receiving triaged tasks under the heading the board owns.
